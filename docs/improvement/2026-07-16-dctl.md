## Proposals (need your call — not applied)

### HIGH · security — secret tokens leak into error strings
`internal/transport/transport.go:88-90` — `h.client.Do` returns its error unwrapped. On any transport failure (DNS/TLS/timeout/ctx-cancel) `net/http` returns a `*url.Error` whose `Error()` embeds the **full request URL**. Several callers put secrets in the path: `Webhooks.Execute` (`/webhooks/{id}/{token}`), `Interactions.Respond/Defer/RespondAutocomplete` (`/interactions/{id}/{token}/callback`), `EditResponse` (`/webhooks/{app}/{token}/messages/@original`). A failed call returns e.g. `Post "https://discord.com/api/v10/webhooks/123/REAL_TOKEN": dial tcp...`, which the host will log verbatim — defeating the `Secret` redaction design.
**Fix:** scrub the URL / strip the token segment before returning; `%w`-wrap a token-free sentinel. Add a test asserting the token never appears in the returned error for token-bearing paths.

### MEDIUM · quality — default resolvers hold `sync.Mutex` across a network call
`defaults.go:37-52, 54-66` — `resolveGuild` and `appIDOnce` lock the shared `d.mu` then do blocking HTTP I/O while holding it. All concurrent callers serialize behind one in-flight request, and a hung guild lookup also blocks appID lookups (shared mutex). The package already uses `sync.Once` (`regOnce`, interactions.go:178) for exactly this.
**Fix:** memoize each value with its own `sync.Once` (or singleflight) so the network call runs lock-free.

### LOW · quality — `UpsertStatusMessage` reimplements message send/edit
`interactions.go:338-356` — hand-builds `/channels/{id}/messages[/{id}]` PATCH/POST, duplicating `Messages.Edit/Send`. Also diverges: `Messages` routes through `resolveChannel`, this doesn't.
**Fix:** route through the `Messages` sub-client; keep only the 404-fallback here.

### LOW · quality — params `min`/`max` shadow Go 1.21 builtins
`commands.go:200,203` (`Range`, `Len`), `components.go:78` (`clamp`). Legal, but a foot-gun in a go 1.23 module. **Fix:** rename to `lo`/`hi`.

### LOW · perf — `Opt*` accessors re-walk the whole option tree
`interactions.go:75-161` — each `Opt/OptInt/OptBool` call recurses from the root; a handler reading N options walks the tree N times. Impact negligible (Discord caps 25 options) — awareness only. **Fix if it grows:** flatten once into `map[string]any` per interaction.

## Verdict
No real bugs, no injection/authz issues. The one thing worth doing soon is the **HIGH token-leak** in transport; the mutex-across-I/O is a good MEDIUM follow-up. Everything else is polish.
